# Findor demo script

Status: preparation only. No recording or publication has occurred.

Target length: three to four minutes.

## Demo flow

1. Open the normal Findor UI and sign in as an ordinary user. Show the private workspace.
2. Enter a generic local-service request with category, plain-language outcome, service area, timing, and context. If required fields are missing, complete them in the UI.
3. Show the standardized Job Brief: requested outcome, structured requirements, and unknowns. Approve it before research.
4. Run the approved bounded provider discovery path. Show relevant provider cards, source URLs, and evidence. Keep website-only and phone-only providers visibly blocked from automated email.
5. Approve a source-backed contactable provider and review the exact subject, recipient, and body. Pause at the send boundary unless explicit outbound authorization is part of the recording.
6. If authorized, click Send this email once and show the truthful external receipt state. Never repeat the action.
7. If a genuine provider reply is available, show the original message, untrusted attachment handling, source-linked interpretation, and comparison. Otherwise show the waiting state and say that no reply has arrived.
8. Show Pause request, Resume request, and the closed-state controls where the fixture state allows. During an active external operation, show that controls are locked.

## Narration

“Findor makes a local-service request clearer without pretending that a lead is a recommendation, a draft is a send, or an interpretation replaces the original provider reply. Public contactability requires retrieved evidence that explicitly publishes a business email. Every external step waits for user approval.”

## Recording rules

Do not show credentials, API keys, deployment keys, cookies, inbox identifiers, message or thread identifiers, exact residential addresses, private employee data, or unrelated customer records. Do not fabricate provider replies, delivery receipts, production URLs, or live states. Label waiting, blocked, failed, and optional states exactly as shown.

## Closing line

“Findor keeps people in control of hiring, payments, contracts, scope changes, and every consequential communication.”
